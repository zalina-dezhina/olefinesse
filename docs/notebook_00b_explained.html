Cell 4 — Detect cracking runsЯчейка 4 — Определение пробегов крекинга
[ 4 ] cracking_mask + segment_runs — the cycle detectorcracking_mask + segment_runs — детектор циклов decoke detection
mask = cracking_mask(feat['feed_total']) # True where feed > threshold = cracking runs = segment_runs(mask) # list of Run objects for r in runs: print(f'Run {r.index}: {r.start.date()} → {r.end.date()} ({r.length_days:.1f} d)')
EN — HOW IT WORKS
cracking_mask(feed_total) returns a boolean Series: True when feed_total > 30% of running level (hydrocarbon feed is flowing = cracking is happening). False when feed drops to ~0 = decoke is happening.

Why NOT temperature? A decoke does NOT cool the furnace — operators burn coke off with steam/air while firing continues. The tubes stay hot. Using temperature would merge many runs into one giant "run" of 43–195 days — completely wrong.

segment_runs(mask) finds contiguous True blocks, with: gaps ≥ 6h split runs (real decoke), blips < 6h do NOT split (sensor noise / brief feed interruption).

Each Run object has: run.start, run.end, run.length_days, run.index.
RU — КАК РАБОТАЕТ
cracking_mask(feed_total) возвращает булеву серию: True когда feed_total > 30% рабочего уровня (углеводородная подача идёт = крекинг происходит). False когда подача падает до ~0 = идёт декокс.

Почему НЕ температура? Декокс НЕ охлаждает печь — операторы выжигают кокс паром/воздухом при продолжающемся горении. Трубки остаются горячими. Использование температуры объединило бы много пробегов в один гигантский "пробег" на 43–195 дней — полностью неверно.

segment_runs(mask) находит непрерывные блоки True, при этом: разрывы ≥ 6ч разделяют пробеги (настоящий декокс), всплески < 6ч НЕ разделяют (шум датчиков / кратковременное прерывание подачи).

Каждый объект Run имеет: run.start, run.end, run.length_days, run.index.
⚠️ Expected output for 1HA: ~16 runs, lengths 5–31 days. If you see runs of 40+ days → cracking_mask threshold may need tuning, or there's a data gap. If you see runs of 1–2 days → feed data has frequent dropouts (check tag quality).Ожидаемый вывод для 1HA: ~16 пробегов, длиной 5–31 день. Если видишь пробеги 40+ дней → порог cracking_mask нужно настроить, или есть пробел в данных. Если пробеги 1–2 дня → частые пропуски данных подачи (проверь качество тега).
Cell 5 — Find analysis windows (the core function)Ячейка 5 — Нахождение окон анализа (ключевая функция)
[ 5 ] find_analysis_window() — where to cut warmup and tailfind_analysis_window() — где обрезать прогрев и хвост 3 criteria
def find_analysis_window(run, feat_df): # Criterion 1: feed at operating level run_med_feed = seg['feed_total'][seg['feed_total'] > 0].median() feed_ok = seg['feed_total'] > FEED_SETTLED_FRAC * run_med_feed # Criterion 2: COT settled (rolling std < threshold) cot_std = seg[cot_col].rolling(COT_ROLL_STEPS, min_periods=2).std() cot_ok = cot_std < COT_STD_THRESH_C # Criterion 3: minimum time past run start time_ok = seg.index >= earliest_start # run.start + 12h # Combined: ALL THREE must be True simultaneously settled_mask = feed_ok & cot_ok & time_ok analysis_start = settled_mask[settled_mask].index[0] # first settled point analysis_end = feed_ok[feed_ok].index[-1] # last point feed still up
EN — THE 3 CRITERIA IN DETAIL
Criterion 1 — feed_ok: Feed must be ≥ 95% of the run's own median. The median is computed per-run (not fixed). This removes: (a) warmup ramp where feed is stepping from 0 up to operational level; (b) pre-decoke tail where operators reduce feed before stopping.

Criterion 2 — cot_ok: Rolling standard deviation of COT over the last 4 hours (8 × 30min buckets) must be < 2°C. During warmup, the COT setpoint is ramped up step by step — std is high. Once the target severity is reached and held, std drops. This catches late settlers (furnaces that need >12h).

Criterion 3 — time_ok: Always skip the first 12 hours no matter what. Even if feed is up and COT is stable, the Delta-Delta baseline is being computed during this window. Including it would mean baseline = signal = circular analysis.

analysis_start = first timestamp where ALL THREE are True.
analysis_end = last timestamp where feed is still at operational level (tail cut).
RU — 3 КРИТЕРИЯ ПОДРОБНО
Критерий 1 — feed_ok: Подача должна быть ≥ 95% медианы собственного пробега. Медиана вычисляется по-пробежно (не фиксированная). Убирает: (а) прогревной разгон где подача ступенями растёт от 0 до рабочего уровня; (б) хвост перед декоксом где операторы снижают подачу перед остановкой.

Критерий 2 — cot_ok: Скользящее стандартное отклонение COT за последние 4 часа (8 × 30мин бакета) должно быть < 2°C. Во время прогрева уставка COT поднимается ступенями — std высокое. Как только целевая жёсткость достигнута и удерживается, std падает. Ловит "поздних" — печи которым нужно >12ч.

Критерий 3 — time_ok: Всегда пропускать первые 12 часов что бы ни было. Даже если подача на уровне и COT стабилен — в этом окне вычисляется базовая линия Delta-Delta. Включить её = базовая линия = сигнал = анализ по кругу.

analysis_start = первый timestamp где ВСЕ ТРИ условия выполнены.
analysis_end = последний timestamp где подача ещё на рабочем уровне (обрезка хвоста).

If settled=False, the function fell back to run.start + 12h — the run may be too short or the feed data is noisy.Результат этой ячейки — win_df — таблица с одной строкой на пробег: run_start, run_end, analysis_start, analysis_end, warmup_hours, tail_hours, clean_days, settled (True/False). EN — WHAT IS REMOVED AND WHY
The logic starts with everything False (excluded) and only sets True inside valid analysis windows. This means 4 categories are removed:

1. Before first complete cycle — no decoke on both sides → incomplete cycle, no run baseline
2. Decoking periods — feed ≈ 0, tubes coated with steam/air, no cracking happening
3. Warm-up (first 12h + unsettled) — Delta-Delta baseline window, COT ramping up
4. Pre-decoke tail — operators reducing feed, conditions not representative

The two added columns: run_id = integer run number (allows you to group/iterate over individual runs), phase='clean' = tag so you always know this DataFrame is the clean version.
RU — ЧТО УДАЛЯЕТСЯ И ПОЧЕМУ
Логика начинает с False (всё исключено) и устанавливает True только внутри валидных окон анализа. Это значит 4 категории удаляются:

1. До первого полного цикла — нет декокса с обеих сторон → неполный цикл, нет базовой линии пробега
2. Периоды декоксования — подача ≈ 0, трубки обрабатываются паром/воздухом, крекинга нет
3. Прогрев (первые 12ч + неустоявшееся) — окно базовой линии Delta-Delta, COT разгоняется
4. Хвост перед декоксом — операторы снижают подачу, условия нерепрезентативны

Две добавляемые колонки: run_id = номер пробега целым числом (позволяет группировать/итерировать по пробегам), phase='clean' = метка что этот DataFrame — чистая версия.

EN — HOW TO READ THE PLOT
Panel 1 — feed_total: Blue = raw data, green = kept. You should see: red at the start of each run (warmup ramp), red at the end of each run (tail), grey between runs (decoke). All clean periods should be at the same high level.

Panel 2 — COT: Purple = raw, dark green = kept. Check that the COT in the green region is flat/stable. If COT is still ramping in the green region → COT_STD_THRESH_C may need to be tightened.

Panel 3 — dd_abs_max: Orange = raw, red-orange = kept. The green shading shows analysis windows. The dashed lines at 30°C (pre-alarm) and 45°C (alarm) are reference levels. You want to see dd_abs_max growing from ~0 at run start to its peak near run end within each green window.

Red vertical bands = warmup + tail (excluded). Grey gaps = decoking periods (excluded). Green bands = analysis windows (kept).
RU — КАК ЧИТАТЬ ГРАФИК
Панель 1 — feed_total: Синий = сырые данные, зелёный = оставлено. Должно быть видно: красное в начале каждого пробега (прогрев), красное в конце (хвост), серое между пробегами (декокс). Все чистые периоды должны быть на одном высоком уровне.

Панель 2 — COT: Фиолетовый = сырой, тёмно-зелёный = оставлено. Проверь что COT в зелёной области ровный/стабильный. Если COT ещё разгоняется в зелёной зоне → COT_STD_THRESH_C нужно ужесточить.

Панель 3 — dd_abs_max: Оранжевый = сырой, красно-оранжевый = оставлено. Зелёная заливка показывает окна анализа. Пунктирные линии на 30°C (предсигнал) и 45°C (сигнал тревоги) — справочные уровни. Должно быть видно как dd_abs_max растёт от ~0 в начале пробега до пика в конце в каждом зелёном окне.

Красные вертикальные полосы = прогрев + хвост (исключены). Серые промежутки = декоксование (исключено). Зелёные полосы = окна анализа (оставлено).
⚠️ Red flags in the plot: (1) Green region starts while feed is still ramping → FEED_SETTLED_FRAC too low; (2) Green region includes obvious COT spike → manual exclusion needed; (3) Very short green windows (<3 days) → run may be too short for reliable correlation; (4) No green at all for a run → settled=False, check that run's data quality.Тревожные признаки на графике: (1) Зелёная зона начинается пока подача ещё разгоняется → FEED_SETTLED_FRAC слишком мал; (2) В зелёной зоне виден явный скачок COT → нужно ручное исключение; (3) Очень короткие зелёные окна (<3 дней) → пробег слишком короток для надёжной корреляции; (4) Нет зелёного ни в одном пробеге → settled=False, проверь качество данных.
Cell 10 — Summary printoutЯчейка 10 — Итоговый вывод
[ 10 ] Final report + suspicious run flaggingИтоговый отчёт + флаги подозрительных пробегов QA check
EN — WHAT TO CHECK
Complete cycles count: Should be runs that have a decoke on both sides. Incomplete cycles at start/end of the time window are expected — they just mean the dataset starts/ends mid-run.

Clean rows %: Typically 60–70%. Lower means more time spent in decoke/warmup/tail (can be legitimate for a furnace with many short runs).

Suspicious runs (warmup or tail > 48h): These are flagged automatically. A warmup of 48+ hours could mean: (a) operators had trouble settling the furnace, (b) feed data has a long gap at run start, (c) the cracking_mask detected the run start too early. Verify each with DCS before including in analysis.
RU — ЧТО ПРОВЕРЯТЬ
Количество полных циклов: Должно быть пробегов у которых декокс есть с обеих сторон. Неполные циклы в начале/конце временного окна нормальны — они означают что набор данных начинается/заканчивается в середине пробега.

% чистых строк: Обычно 60–70%. Ниже значит больше времени в декоксе/прогреве/хвосте (может быть нормально для печи с много короткими пробегами).

Подозрительные пробеги (прогрев или хвост > 48ч): Флагуются автоматически. Прогрев 48+ часов может означать: (а) операторы долго выводили печь на режим, (б) данные подачи имеют длинный пробел в начале пробега, (в) cracking_mask обнаружил начало пробега слишком рано. Проверить каждый в DCS перед включением в анализ.
